## 編集から公開まで
1. `/admin/news` を開く。現在デプロイされている記事を読み込む。GitHub側が先行している場合は、最新 `content/news.json` を取得してフォームの「読み込む」で開く。
2. 記事ID（URLになる半角英小文字/数字/ハイフン）、日本語タイトル/本文、表示日を入力。英語はタイトルと本文の両方を任意入力。空なら英語ページにも日本語を表示。
3. プレビュー後「編集内容を一覧へ追加」。ここではブラウザのメモリのみ変更し、公開もサーバー保存もしない。
4. `news.jsonを書き出す`。入力中の原稿は先に一覧へ追加する。タブを閉じると未書出の原稿は失われる。
5. 「GitHubで登録」から `content/news.json` を開き、書き出したJSONを反映。**新しいブランチでPRを作成**する。最新版との差分を確認し、他の人の記事を上書きしない。
6. PRレビューとデプロイ後、日英一覧・詳細・トップを確認。表示日は並び順用で、予約公開機能ではない。

リポジトリはpublicです。PRへ含めた原稿も第三者に読めるため、非公開の下書きはGitHubに登録せず手元のファイルで保持してください。JSONには公開対象の記事だけを含めます。公開停止は記事を一覧から外したJSONのPRとデプロイで行います。

## 公開側
- `/ja/news`、`/en/news`：全記事一覧（正本は最大1000件）。
- `/{lang}/news/{id}`：記事詳細。不正IDや存在しないIDは404。
- トップ：最新5件。記事0件のとき欄を非表示。
- 本文はプレーンテキスト、HTMLとして解釈しない。表示順は表示日降順、同日はID順。
- 読取元はデプロイ済みJSON。DB接続や保存APIはない。公開APIにはGitHubトークンや非公開原稿を渡さない。

## 旧CMSの扱い
公開レイアウトからSupabaseのAuthProviderを除去しました。旧 `/admin/login` や観光施設のDB保存画面は表示せず、Gitでの更新案内を出します。旧コンポーネント/API/SQLは残存資料であり、現在の公開データの編集先ではありません。

## 受入条件・検証
- 環境変数なしで公開サイト・お知らせ編集が起動/ビルドできる。
- 原稿入力→プレビュー→一覧追加→JSON書出→再読込ができる。入力不足/不正日付/ID重複/片側のみ英訳は拒否する。
- JSONの各記事に日英表示と安定した詳細URLがある。記事の追加・削除はGit差分で確認できる。
- `npm run test:news`、`npx tsc --noEmit`、`npm run build -- --webpack`。
- Git管理の手順を使うため、PRレビュー/デプロイ前に本番が変わらない。
