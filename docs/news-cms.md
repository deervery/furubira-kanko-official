# お知らせ管理（タスク86・レビュー用）

## 確定している依頼
観光協会WEBサイトでニュースを登録できるようにする。変更はDraft PRまでとし、本番反映・DB変更はまだ行わない。

## このPRの実装案
既存Supabase認証を使い、管理ダッシュボード → お知らせ管理で作成・編集・下書き・公開・非公開を行う。入力は日本語タイトル/本文/表示日、英語タイトル/本文は任意。英語未入力時は日本語を表示する。本文はプレーンテキスト、HTMLはReactのエスケープ対象。保存前プレビューを用意。削除は提供せず非公開に戻せる。表示日は予約公開ではなく表示・並び順用（公開保存で即公開）。最新100件を一覧表示、トップは5件。画像・添付・カテゴリ・予約公開・100件を超えるページングはこの第一版の対象外。

公開先は `/ja/news`、`/en/news`、`/{lang}/news/{id}` とトップのお知らせ欄。匿名クライアント + 公開条件 + RLS の三層で下書きを隠し、取得はno-store。トップのお知らせ欄はブラウザ取得なので既存ホームISRの1時間を待たず次回アクセスで反映。障害時は既存ホームを維持し、ニュース一覧・詳細では取得失敗を表示。

## レビュー後の導入手順（まだ未実施）
1. ステージングSupabaseに `docs/sql/07_create_news.sql` を適用。既存テーブルが同名で存在した場合は停止し、内容を確認する。
2. 指定担当者の Supabase Auth `app_metadata.news_editor` を管理者の信頼できる環境でboolean `true`にする。他のメタデータを保持する。ユーザー編集可能なuser_metadataを使わない。サービスロールキーをブラウザやリポジトリに保存しない。担当者は再ログインする。
3. 既存のNEXT_PUBLIC_SUPABASE_URL/ANON_KEYをステージング向けに設定し、下記受入確認。
4. 本番適用はユーザーの反映指示後。DB migrationと編集権限を先に準備、次にコードを反映。

## 受入条件
- 権限付き担当者が下書きを作成・再編集・プレビューできる。
- 匿名・権限なしログインでは直接Supabase API経由でも下書きが読めず、insert/update/delete不可。編集者にも削除権限なし。
- 公開すると一覧/トップ/詳細へ表示、非公開に戻すと直接URLも404になる（次回リクエスト）。
- 日本語・英語翻訳と日本語フォールバック、改行、日本語/英語ページを確認。
- 空入力/無効日付/片側だけの英語翻訳/文字数超過は拒否。DB側にも必須・文字数・英語ペア制約。
- 保存エラー時は入力を保持。更新競合はupdated_at条件により上書きせず再読み込みを促す。
- 320px画面で管理/公開が読めること。キーボード操作可能。
